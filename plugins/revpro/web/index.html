Getting started

sites.conf — site definitions

Sites are grouped by domain. A ==domain header opens a group and may set group-wide defaults; each line below it is one site under that domain.

# <name>  <target>  [flags]  [--cert="name"]
==example.tld
@        10.0.0.1:8443            # apex → example.tld
api      10.0.0.2:8443  +s       # api.example.tld, https upstream
status   10.0.0.3:8080  -w       # no www variant
admin    10.0.0.4:8443  --cert="admin-cert"

==apps.tld [A] <+s>              # machine A + https for the whole block
@        8443                    # port only → A:8443
grafana  :3000                   # ":port" works too
wiki     3001  -s                # overrides the group's +s
backup   B:9000                  # full target overrides the group machine

Flags

Each +x enables, -x disables; resolved global → group → line.

FlagMeaningDefault
aAuthentik auth-proxy in front of the siteoff
sUpstream speaks HTTPS (else plain HTTP)off
wAlso serve www.<domain>on — use -w to disable
lLocal-only access (include local.conf)off

The cert name defaults to the site's full domain unless --cert="name" is given — handy when several sites share one certificate.

machines.conf — machine slugs

Short codes (1–8 letters/digits, starting with a letter, case-insensitive) that stand in for whole addresses anywhere a machine is named.

# slug   host
A        192.168.2.20
AVA      192.168.2.30
AVA01    192.168.2.31
N        192.168.2.100

Use them in sites.conf targets (app  A:8080), in group headers (==apps.tld [A]), in revpro port suggest A web, and in this UI's machine fields. Generated nginx configs always receive the resolved host.

ports.conf — port ranges & suggestion

One category per line; ranges are inclusive, multiple ranges and single ports allowed.

# category   ranges
web        3000-3999
apps       8000-8099 8200-8299
db         5400-5499

Suggestion logic — for a machine and category, revpro takes the next port after the highest one that machine already uses inside the category's ranges (sequential allocation), wrapping to the first gap when the tail is exhausted. Candidates are TCP-probed so a port with a live listener is never suggested. A firewalled host that drops packets looks free — probing is best-effort and can be turned off.

Bootstrapping a brand-new domain

nginx can't start without its certs, and certs need port 80 — revpro breaks the deadlock by answering the ACME challenge itself:

docker compose stop reverseproxy    # 1. free :80
revpro issue                        # 2. revpro answers HTTP-01 on :80
docker compose up -d reverseproxy   # 3. certs exist → nginx starts

Once running, set REVPRO_ACME_WEBROOT=/revpro/letsencrypt so future renewals go through the running nginx and nothing needs stopping.
